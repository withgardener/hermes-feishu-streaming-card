# v5.0.0：任务分区阅读、交互续答与维护边界

V5 汇总任务分区阅读、交互续答、本轮统计和维护流程改动。正式发行以 GitHub Release 的版本标签及校验后的资产为准。

## 面向使用者的变化

- `task` 预设采用已确认的任务分区方向：状态色标题、可展开/收起的执行过程和优先显示的正文。减少标题、当前动作、工具摘要的重复；保留完成历史和失败证据。过程标题在手机展开、收起时不再使用误导性的固定方向符号。
- 真实交互继续使用 Hermes 原授权与输入处理。交互后成功创建续答消息、且平台返回合法消息链接或可验证的同一回执定位信息时，旧卡可提供“查看续答”；创建失败、链接来源不明或预算不足时不编造目标。
- `card-config --running` 区分服务已经加载的配置与文件下次加载值；无法核对进程和范围时明确不可用。`--minimal-yaml` 输出保留当前合并结果的阅读配置片段，支持已有离线预览。
- `task` 旧段在续答明确送达后保留蓝色转交标题，将支持安全折叠的历史默认收起，避免旧段与最终过程同时展开重复；未知组件或容量不足时保留原卡，不删除历史。
- 工具拒绝和超时来自匹配的原始审批回调或原澄清等待的自然超时，显示明确终态；同轮重试保持结果。显示记录达到上限后保守显示“结果待核对”，不误报执行成功；不改变 Hermes 的执行或授权。
- 最终卡恢复本轮模型、供应方、用时、token 和上下文统计。只显示实际取得的数据；缺失数据不补零或虚构。用时包含交互等待，上下文容量取本轮对应 Agent 的实际配置，token 汇总本轮请求，不拿会话累计量代替。
- 澄清问题交付成功后复用原交互所有者，减少卡片之外重复出现的原生问题。回执丢失时通过带身份签名的只读送达核验确认；无法证明送达仍保留原生回退，不能承诺所有网络故障下绝无重复。
- 诊断保留原生交接告警，插件启用阶段可区分命令失败与配置所有权拒绝；未知异常不直接向用户输出原文。

## 结构与可靠性

事件、交互输入与回执、显示投影、终态投递、配置规则、进程清理及安装证据分别归属明确模块。配置、传输错误与安装家族的循环依赖已消除，实际来源、锁、授权和提交顺序仍由原执行所有者负责。

官方插件事件在开始、工具、流式正文和终态之间保留同一 profile 身份，避免同一轮任务分裂为两份卡片状态。流式增量使用既有协议阶段；最终投递使用原定的有界确认预算，收到明确卡片回执后才抑制原生正文。已启用插件的安装允许 Hermes 保留原启用列表，其他配置仍受精确比对和恢复保护。

实际 Gateway 的正常返回、空结果和排队续轮保留终态回执，直到最终投递决策再消费；只有结果未被 Gateway 改写且卡片已接管时才省略原生文本。原生工具进度也按当前轮、会话、profile 与存活所有者判断，覆盖排队尾部和取消路径。含 `MEDIA:` 的结果继续交给原生路径，优先保留附件，不承诺该路径没有重复。

已验证的历史 `terminal_disposition` 单片段 revision 安装支持官方恢复后重装；旧版本不会被误报为已应用新接线。未知漂移仍拒绝修改，不放宽源码所有权校验。

统计接线包含官方 `post_api_request` 事件，安装器核对真实 PluginManager 注册结果。缺少该事件仍拒绝安装，不因增加 footer 而放宽能力验证。交互送达确认不刷新等待者或改变过期时间；请求、响应大小和总时限均有边界，已取得的交互所有权不会因延迟回执而撤销。

安装和恢复共用目录绑定 I/O，保留并发替换识别、写入前复核、回滚及清理失败处理。源码所有权检查与事务执行分离。callback 补丁每次验证唯一目标，已存在 marker 不能代替真实接线证明。更新了固定 Hermes v0.22.0 / main 的源码兼容矩阵；这些源码检查不等于所有版本都完成真实运行验收。

## 升级与兼容

- 延续原安装、配置与服务管理入口；不要手改 Hermes 安装源码。
- `task` 仍主动启用。其他预设和显式覆盖保持；希望过程默认折叠时设 `card.timeline_expanded: false`。
- 原生表格仍默认关闭，超长单元格整表回退完整 Markdown。新旧布局都不得截断最终答案或授权范围。
- Python 支持范围不因 V5 名称自动提高。现有公开导入对象保留所需兼容名称，不新增第二套实现。
- GPT 订阅额度仍要求本轮实际使用 GPT 与 `openai-codex`；普通 API key、其他模型或仅本机登录不会据此显示额度。

## 验证边界

自动化覆盖原始 Hermes 工具与 Gateway 调用路径、签名 HTTP 交互、普通包安装来源、受管补丁和精确恢复。完整 Python/平台矩阵、合并提交、annotated tag、资产校验和公开安装按[发布手册](wiki/release-playbook.md)核对。真实飞书执行、桌面显示、手机显示和按钮跳转分别记录，不用单元测试替代真人点击。iOS 与五位新用户试用未纳入本次验收，不宣称通过。

Hermes 固定版本的实际 Gateway 验证与最新 stable/main 的源码兼容检查是不同范围。分离 HOME/共享源码、多 Gateway 等布局仍遵循既有身份校验和安全拒绝限制，不因版本号变化自动扩大支持。
