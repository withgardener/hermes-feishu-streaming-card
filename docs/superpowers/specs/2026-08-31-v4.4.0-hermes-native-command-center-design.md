# V4.4.0 新版 Hermes 原生能力中心设计

日期：2026-08-31
状态：实现完成，发布候选验收中
目标版本：Hermes Feishu Streaming Card V4.4.0

## 1. 版本基线

本版本不是基于旧命令清单扩展，而是基于 2026-08-31 实时核对的新 Hermes 契约设计：

- 最新正式 Release：`v2026.8.27` / Hermes Agent `0.20.6`。
- 最新 `main`：`4f22543509d1b91dc45bcb369447126c5eb14fb7`（2026-08-30）。
- 本机安装目录存在 HFC patch 和运行状态，且落后远端，因此只用于兼容观察；设计基线来自独立只读的最新上游检出。
- Hermes 已把 gateway、CLI、Telegram、Slack、Desktop 等命令元数据集中到 `hermes_cli.commands.COMMAND_REGISTRY`。
- 独立加载最新 main 的 registry 后，当前可见 66 个 Gateway 命令；这个数字只作为本轮兼容证据，运行时仍以实际 registry 为准。

新版注册表可以提供：

- `name`、`category`、`description`、`aliases`；
- `args_hint`、`subcommands`、`argument_mode`；
- `cli_only`、`gateway_only`、`gateway_config_gate`；
- `busy_policy`、`busy_handler`、`desktop`；
- plugin command 与 skill command 的扩展入口。

`v2026.8.27..main` 还出现了直接影响飞书体验的变化：`/background` 拆成语义不同的 `/bg` 与 `/btw`，新增 `/plan`，`/busy` 进入 Gateway，命令新增 Desktop argument/availability 元数据。HFC 不应再复制固定 allowlist。

## 2. 用户问题

V4.3.x 已经解决流式卡、模型/会话 picker、命令确认、clarify 和运维诊断，但飞书中的 Hermes 仍有四个体验断层：

1. 命令发现主要依赖多页 Markdown 文本，新命令上线后 HFC 展示容易滞后。
2. `/status`、`/context`、`/usage`、`/agents` 等原生能力虽已卡片化，但信息层级仍接近文本转贴。
3. `/model`、`/resume` 有原生交互，其他只读命令仍必须记忆和输入。
4. 高频流式更新的 `update_queue_peak` 只记录 0/1，不能反映真实合并压力。

## 3. V4.4.0 产品目标

### 3.1 Hermes 原生能力中心

`/commands` 在飞书中升级为动态能力中心：

- 运行时读取当前 Hermes 的 `COMMAND_REGISTRY`；
- 按 Session、Configuration、Tools & Skills、Info、Plugins、Skills 分类；
- 支持分类切换、命令详情、alias、subcommand、argument mode 和 busy policy 展示；
- 发现 plugin/skill commands 时自动加入，不修改 HFC 源码；
- Hermes 注册表不可用时 fail-open，继续发送原 `/commands` 文本。

### 3.2 安全快捷入口

能力中心提供少量一键入口：`/status`、`/context`、`/usage`、`/agents`、`/sessions`、`/model`、`/resume`、`/reasoning`、`/profile`、`/version`。

快捷执行必须：

- 复制原入站 `MessageEvent`，不修改原事件；
- 重新进入 Feishu adapter 的 `handle_message`，继续经过 Hermes command resolution、busy policy、access control、plugin hooks 和原 handler；
- 群聊只允许原发起人点击，且继续通过 Hermes `_allow_group_message`；
- `/update`、`/new`、`/stop`、`/undo`、`/pause`、`/yolo` 等改变状态或破坏性的命令不提供一键执行；
- 需要自由文本或显式参数的命令只展示完整用法，由用户在消息框确认。

### 3.3 原生结果可视化

下列原生命令输出增加信息层级，但保留完整原始文本：

- `/status`：Hermes 运行状态；
- `/context`：上下文视图；
- `/usage`：用量与限额；
- `/agents`：活跃 Agents；
- `/sessions`：历史会话；
- `/profile`、`/version`、`/reasoning`、`/fast`、`/busy`。

可识别的 `Label: Value` 信息提升为 KPI columns，原文本继续作为完整详情，不能因可视化丢字段。无法稳定识别时只展示原文本。

### 3.4 流式压力与内容可靠性

- `FlushController.pending_count` 改为真实记录一次 PATCH 执行期间被合并的更新次数；`update_queue_peak` 反映真实 backlog peak，不再是布尔值。
- 表头或行结构无法在合法 Markdown block 内拆分时输出明确安全折叠提示，不产生损坏的 raw table fragments。
- 普通长表格、超长单元格、五表格 policy、200 element / 28,000-byte budget 和 terminal native handoff 不变。

## 4. 架构边界

### Hermes 拥有

- 命令定义、可用性、alias、参数和 busy policy；
- 命令权限、session ownership、plugin hook 与真实执行；
- `/model`、`/resume`、confirm、agent turn 和原生文本 fallback。

### HFC 拥有

- 注册表快照的有限期卡片状态；
- 飞书分类、详情、KPI 和按钮布局；
- card callback 的 chat/operator/expiry 校验；
- 把允许的一键动作交回 Hermes 原入口；
- 卡片发送失败后的精确原生文本 fallback。

HFC 不新增 Hermes 命令，不手改 `gateway/run.py`，不复制命令执行语义。

## 5. 失败与升级策略

- 新版注册表 import、config gate、plugin/skill discovery 任一步失败，只缩减能力中心内容，不中断 Hermes 命令。
- 互动状态 10 分钟过期、每 adapter 最多保留 64 个，过期或超限按 FIFO 清理。
- callback chat 不匹配、操作者不可验证、群聊非原发起人、命令已从注册表消失时拒绝执行。
- 卡片 create/PATCH 失败时保留既有精确 native text fallback。
- 正式兼容基线为 `v2026.8.27 / 0.20.6`；同时用 `main@4f225435` 验证向前兼容。

## 6. 验收矩阵

### 自动化

- 动态读取最新 Hermes registry，并识别 `/bg`、`/btw`、`/plan`、`/busy` 与 argument mode。
- `/commands` overview、category、detail 和 safe quick action card JSON。
- 只读快捷动作使用 copied event 回到 adapter；状态变更命令无法一键执行。
- 私聊、群聊发起人、非发起人、过期 state、错误 chat 与重复 callback。
- native result KPI 可视化不丢原始文本。
- backlog depth、极端 Markdown、hook/server/card-limit 回归。
- 完整 pytest、`git diff --check`、sdist/wheel 和 fresh-wheel provenance。

### 真实飞书

- 私聊：`/commands` 分类/详情，点击 `/status`、`/model`、`/resume`。
- 群聊：发起人可以导航和运行只读命令，其他成员不能代为执行。
- `/status`、`/context`、`/usage` 的 KPI 卡片与原始详情均可见。
- 卡片 callback 后不出现重复灰色文本；失败时可见原生 fallback。
- 极端表格只显示安全折叠提示，不显示损坏 Markdown。

真实飞书验收只在实际客户端观察完成后记录，不以 mock 或 HTTP fixture 冒充。
