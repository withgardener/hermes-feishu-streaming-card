# V4.0.21 Content Integrity Hotfix Design

## Goal

V4.0.21 is a narrow content-integrity hotfix for Issue #155, with a combined
media/notice regression for Issue #147. It must prevent a streamed final answer
from being archived merely because some tool ran earlier in the turn, while
preserving the existing media handoff, notice acknowledgement, card layout, and
fail-open behavior.

## Scope

The production change is limited to answer/tool ordering in `CardSession`.
V4.0.21 does not add configuration, change the card layout, parse Hermes-private
verification markers, or include the routing, table-overflow, upgrade-guard, or
systemd work planned for V4.1.0.

Issue #147 is handled evidence-first. V4.0.20 already aligned queued
`system.notice` acknowledgement with the runtime hook. V4.0.21 adds a combined
regression and performs a real Feishu image smoke. Production code changes for
that issue are allowed only if the combined regression or real smoke exposes a
new root cause.

## Answer Ordering Invariant

An answer segment may move into the reasoning timeline only when a tool event
occurred after that exact segment began.

The ordering rules are:

1. `answer -> tool`: the answer segment has an explicit later-tool boundary and
   may be archived as interim reasoning.
2. `tool -> answer -> completed`: the answer is the post-tool user-visible
   candidate and must not be archived because of the earlier tool.
3. `answer -> tool -> answer -> tool -> completed`: each answer segment followed
   by a tool may be archived in order; the terminal answer remains visible.
4. A turn-wide "has seen a tool" flag is never sufficient evidence to archive
   the current answer.

`_answer_archive_index` is the existing ordering proof. It is set only when a
tool arrives while the current answer is non-empty. Completion reconciliation
must use that proof and must not fall back to `_has_seen_tool_event` heuristics.

## Completion Reconciliation

When there is no explicit later-tool boundary for the current answer,
`message.completed.answer` remains the authoritative completed representation.
If it extends the streamed answer, the whole completed value is shown once; the
streamed prefix must not be stripped or inserted into the reasoning timeline.

The hotfix does not infer a "verifier" from text length, language, keywords, or
Hermes-private `finish_reason` values. A future structured assistant-segment
protocol may support a separate supplemental section, but that is outside this
release.

MEDIA and attachment paths retain their existing terminal semantics. The hook
continues to clean `MEDIA:` directives, attach safe summaries, and mark
`native_delivery=required`; `CardSession` displays the completed text provided
by that path.

## Issue #147 Combined Behavior

For one image-producing turn:

- the completed event is accepted by the sidecar;
- the visible text is carried by the card once;
- the matching native media text is suppressed once;
- the actual image continues through Hermes' native media sender;
- an accepted queued system notice does not produce the uncertain-delivery
  warning;
- unrelated later native text is not suppressed.

The real Feishu acceptance result must be one completed card plus one native
image, with no gray duplicate answer and no uncertain-delivery warning.

## Compatibility And Safety

- Event schema remains `"1"`.
- Unknown or unsupported runtime paths remain fail-open.
- No new Hermes source-patch anchors are introduced.
- No credentials, chat ids, local paths, model content, or raw hashes are added
  to logs, docs, health, fixtures, or release evidence.
- Existing #96 punctuation/short-suffix behavior and all media/notice behavior
  remain covered.
