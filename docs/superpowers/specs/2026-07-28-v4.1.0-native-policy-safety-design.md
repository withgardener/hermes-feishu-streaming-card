# V4.1.0 Native Policy And Runtime Safety Design

## Goal

V4.1.0 completes Issues #157, #158, and #159 and replaces the unsafe parts of
PRs #156 and #160. The release gives each Feishu/Lark chat an explicit choice
between HFC cards and Hermes native messages, preserves all table content within
Feishu card limits, detects when a Hermes upgrade has removed the active hook,
and makes sidecar process-manager selection explicit without silently crossing
into system privileges.

The default user experience remains unchanged: existing chats continue to use
streaming cards, existing installations remain in notification-only integrity
mode until explicitly migrated, and ordinary Linux installations never prompt
for or assume root access.

## Scope And Non-Goals

V4.1.0 includes:

- exact, profile-scoped `bindings.native_chats` overrides;
- a signed hook-to-sidecar delivery-policy protocol;
- card-table overflow compaction and an exact serialized-card budget guard;
- signed runtime hello/heartbeat integrity monitoring;
- verified safe repair of stale HFC install state without an automatic Gateway
  restart;
- explicit `service.manager` selection for user systemd, detached processes,
  and opt-in transient system systemd units;
- ordinary Docker Compose operation with no systemd dependency.

V4.1.0 does not:

- add wildcard, regex, prefix, or global-disable chat matching;
- change an already-running turn from card to native or native to card;
- add table pagination or silently discard table rows;
- restart the Hermes Gateway automatically;
- install persistent `/etc/systemd/system` units;
- monkey-patch `hermes_cli/gateway.py` at import time;
- edit an installed Hermes file outside the existing patcher/recovery paths.

## 1. Per-Chat Native Delivery Policy

### Configuration And Matching

The configuration surface is:

```yaml
bindings:
  native_chats: []
```

In multi-profile mode the active list is only
`profiles.<profile_id>.bindings.native_chats`. It does not inherit or merge the
top-level list. Values must be non-empty strings without control characters,
are deduplicated while preserving order, and are matched exactly. Wildcard-like
values are rejected rather than interpreted.

An unknown profile, unreadable configuration, or invalid configuration is a
safe native decision. Diagnostics expose only counts and masked short hashes;
they never expose a raw chat id.

### One Policy Owner And Hot Reload

`delivery_policy.py` owns `ChatDeliveryDecision`, configuration parsing, exact
matching, and a bounded mtime-based provider. A successful CLI mutation is
visible to the next new message without restarting the sidecar. If a reload
fails, the provider does not keep serving a stale card decision; it returns
native until a valid snapshot can be read.

The policy is fixed for one active turn:

- an existing active `CardSession` remains a card turn;
- a completed session followed by a new `message.started` is a new turn and
  reads the current policy;
- the first answer/tool/completed event may establish a new turn when Hermes did
  not emit `message.started`;
- a duplicate terminal event for an already-completed card remains handled and
  cannot leak a second native answer.

### Signed Policy Protocol

The sidecar exposes `POST /delivery/policy`. The request is authenticated even
on loopback with a distinct `hfc-policy-v1` signing domain, a maximum five-second
age, and nonce replay protection. It carries schema version, chat id, profile
id, and the available turn/message identity. The response never echoes an id:

```json
{
  "ok": true,
  "disposition": "native",
  "reason": "bindings.native_chats",
  "ttl_ms": 1000
}
```

Missing secrets, invalid/expired/replayed proofs, malformed payloads, unknown
profiles, timeouts, non-2xx responses, and malformed responses all cause the
hook to fail open to Hermes native delivery.

### Two-Stage Enforcement

The hook queries policy before it creates/coalesces an event or returns `True`
to a Hermes callback. Its cache is thread-safe, bounded, profile/chat/endpoint
scoped, and at most one second. Terminal events clear per-turn decisions,
pending deltas, and native-media suppression state.

The sidecar independently checks policy before creating `CardSession`, alias,
animation, or Feishu client state. A native event returns:

```json
{"ok": true, "applied": false, "disposition": "native"}
```

It increments native-policy metrics but not `events_ignored`. This server check
is a final safety boundary; it cannot replace the hook preflight because Hermes
callbacks would otherwise already have been swallowed.

All direct card paths share the same decision: normal answer/thinking/tool
events, approval/clarify, cron, system notices, command feedback, `/new`,
`/model`, `/resume`, `/compress`, slash confirmations, model/resume pickers, and
native media handoff. A native decision calls the original Hermes path or
returns false so Hermes does so. `200 + applied:false` is not delivery success.

`/hfc help`, `/hfc status`, `/hfc doctor`, `/hfc monitor`, card actions, and the
explicit smoke-card command remain card-based management surfaces.

### CLI

```bash
hermes-feishu-card chats use-native CHAT_ID --config CONFIG [--profile-id ID]
hermes-feishu-card chats use-card CHAT_ID --config CONFIG [--profile-id ID]
hermes-feishu-card chats list --config CONFIG [--profile-id ID]
```

Mutations are atomic and idempotent. Multi-profile configuration requires an
explicit existing profile. Output is masked, never prints the supplied raw id,
and states that the next new message is affected.

## 2. Table Overflow Without Data Loss

### Card Configuration

```yaml
card:
  table_overflow_mode: compact  # compact | truncate
```

`compact` is the new default. `truncate` preserves the legacy behavior for
operators who explicitly choose it. The setting is profile- and bot-card aware
through the existing card-config merge rules.

### Markdown-Aware Parsing

Table recognition uses the existing markdown block scanner, not a global regex
or pipe counter. A table begins only when a valid header row is immediately
followed by a valid separator row outside fenced code. Escaped pipes, inline
code, blank-line block boundaries, and fenced fake tables must not change the
count.

At most five markdown table blocks remain as Feishu tables. In compact mode,
table six and later are converted in source order to readable field lists:

```text
Table 6
- Column A: value
- Column B: value
```

Every row and cell remains present. Duplicate/empty headers receive stable
fallback labels. One localized note explains that later tables were compacted
for Feishu compatibility. In truncate mode the legacy five-table limit and
single truncation note remain, but fenced fake tables no longer consume the
limit.

### Serialized Card Budget

The authoritative limit is measured on the UTF-8 encoded JSON generated for the
actual card, not on markdown character count. HFC keeps a conservative 28,000
byte budget below Feishu's 30 KB/200-element boundary.

If compact rendering still exceeds the safe budget, HFC must not send a partial
answer. A non-terminal oversized render uses a fixed small waiting card and
continues collecting the turn; deltas are not leaked as native fragments. At
terminal, HFC replaces an existing card with a short, non-sensitive handoff
notice and returns `applied:false, disposition:native`; Hermes then sends the
full final answer natively once. If no card exists at terminal, it sends no
extra handoff card and returns native directly. This terminal disposition is
persisted and idempotent, so a duplicate completed event has the same handoff
semantics without changing or losing the original answer.

### Native Handoff Delivery Acknowledgement

Persisting only the sidecar decision is insufficient: a Gateway can crash
after that decision is durable but before Hermes sends the native answer. The
handoff therefore uses an explicit capability-negotiated delivery protocol.
The sidecar keeps the handoff-card notice state separate from native-delivery
state and returns an opaque, stable handoff descriptor while native delivery
is unacknowledged. A repeated terminal event within the retry window receives
the same descriptor and remains `applied:false`; only a signed delivery ACK
turns later repeats into `applied:true`.

The runtime carries the descriptor only in a turn-scoped `ContextVar`. The
existing Feishu adapter wrapper derives a distinct stable UUID for every
logical native chunk and reuses that UUID across adapter-internal retries,
Gateway-level retries, and reply/create fallback. Markdown-post and plain-text
fallback are separate format variants, and identical adjacent chunks remain
distinct by ordinal. Every required chunk must succeed before the runtime ACKs
the handoff; success of the last chunk cannot hide an earlier failure.

Hermes 0.19 also has a durable delivery ledger. The patcher-owned startup hook
must be installed before ledger recovery, and a minimal owned recovery hook
passes the obligation identity and original delivery context back to the
runtime. It must not replace or copy the upstream recovery method. Unsupported
anchors or private adapter capabilities fail open and surface manual review
rather than claiming protected delivery.

The ACK endpoint uses the same private transport root with a separate signing
domain, bounded timestamp, and nonce replay protection. State, health, logs,
fixtures, and public diagnostics never expose the descriptor seed, raw ids, or
answer content. Feishu UUID deduplication is time bounded (about one hour), so
this is not a mathematical forever-exactly-once promise: ACKed delivery is
deduplicated, retries inside the UUID window are effectively once, and an
unresolved handoff beyond the window becomes uncertain/manual-review instead
of being resent forever. Hermes' visible recovered marker remains the honest
fallback outside that window.

No content-dependent error details or answer excerpts are added to health or
logs. Metrics expose only counts of compacted tables and native budget handoffs.

## 3. Runtime Integrity Monitoring

### Configuration And Migration

```yaml
integrity:
  mode: safe  # safe | notify | off
```

New setup/example configurations explicitly select `safe`. The in-code default
for a missing section is `notify`, so an upgraded existing config does not begin
mutating install state without an explicit migration. `off` disables the
control plane but not ordinary event authentication or manual diagnostics.

The CLI exposes a deliberate mode mutation and explains the migration boundary.
It never writes raw transport secrets or paths to output.

### Authenticated Control Plane

The installed Hermes runtime sends `runtime.hello` at startup and periodic
`runtime.heartbeat` messages on a daemon thread. Requests use a separate
domain-separated HMAC proof, a short age window, and replay protection. The
thread resolves the current private transport on every attempt so a sidecar
restart/secret rotation can recover without a Gateway restart. Network,
signature, import, and sidecar failures are fail-open for Hermes work.

The sidecar records only sanitized runtime facts and monotonic receipt times.
It does not trust caller-supplied file paths or hashes as permission to mutate.
The first heartbeat has a startup grace period; missed heartbeats degrade
readiness without changing the top-level process-health HTTP semantics.

### Health And Recovery State

`GET /health` keeps HTTP 200 while the sidecar process is alive. It adds a
sanitized readiness object with states such as `ready`, `waiting`,
`runtime_missing`, and `restart_required`. `/hfc status`, `/hfc doctor`, and
`/hfc monitor` render the same state and actionable next step without claiming
`sidecar: healthy` when card delivery is not ready.

In `notify` mode, strict evidence creates an operations alert and recovery plan
but does not mutate. In `safe` mode, HFC may execute only an already-supported,
executable recovery plan after a fresh fingerprint recheck. Automatic repair is
stricter than the manual `--accept-hermes-upgrade` path: a migrated manifest
must prove the prior Git HEAD and owned target blobs, the current HEAD must be a
descendant, the current unpatched targets must exactly match current HEAD, and
the patch must remain reversible with supported anchors. Source-stripped roots,
dirty targets, rewound branches, symlinks, user edits, old manifests, corrupt or
mismatched artifacts, and changed evidence are never auto-repaired. A valid
plan may clear verified stale HFC artifacts and reinstall only through the
official patcher/recovery transaction.

Successful repair sets `restart_required=true`. HFC never restarts the Gateway
automatically because doing so would interrupt active conversations. Health,
CLI, doctor, logs, and operations cards expose one deduplicated action. A
proactive Feishu alert is sent only to an explicitly configured administrator
destination, never to an inferred recent chat. Repeated heartbeats do not spam
alerts or rerun a repair.

The runtime hook starts from the existing patcher-owned startup adapter call, so
an upgraded HFC package can add the monitor without a broader Hermes source
patch. Legacy supported paths may lazily start it on first hook entry. Marker
detection, removal, restore, and patcher idempotence remain covered. PR #160's
import-time monkey patch is not used because supported Hermes
still invokes `gateway.run.start_gateway`; an import bridge would be broader and
less verifiable than the existing AST-owned hook.

## 4. Explicit Sidecar Service Management

### Configuration

```yaml
service:
  manager: auto  # auto | systemd-user | systemd-system | detached
```

Selection semantics:

- `auto`: use `systemd-user` only when its manager is available; otherwise use
  `detached`. It never attempts system-level systemd and never prompts for sudo.
- `systemd-user`: require a working user manager or fail with a precise
  remediation message; do not silently fall back.
- `detached`: use the existing owned detached-process path on every platform.
- `systemd-system`: explicit Linux-only opt-in. Use transient
  `systemd-run --system`/`systemctl --system` units only; never create persistent
  files under `/etc`, never invoke `sudo`, and fail clearly when the caller lacks
  permission.

PID records include the selected manager and stable unit identity. Start,
status, migration, and stop verify manager/unit/token ownership; an unknown unit
or process is never killed. A configuration-manager change performs only the
existing verified owned-process migration and otherwise fails closed.

PR #156's automatic system-service fallback is not accepted because `auto`
must not cross a privilege boundary. Its user-systemd availability observations
are retained as tests for explicit behavior.

### Docker

Docker Compose runs the sidecar as its ordinary container process and does not
attempt systemd. Installer/docs make the detached/container boundary explicit.
No Docker image receives systemd or elevated host privileges for this feature.

## 5. Security And Privacy Invariants

- Event, policy, and runtime-control proofs use distinct signing domains.
- Every authenticated endpoint has bounded timestamp and nonce replay checks.
- Chat ids, app secrets, transport secrets, local absolute paths, message
  content, and raw recovery fingerprints never enter health, metrics, logs,
  fixtures, screenshots, CLI listings, issue comments, or release notes.
- Hook behavior is fail-open to Hermes native output; installer/recovery
  mutations are fail-closed.
- Only `hermes_feishu_card/install/patcher.py` and existing verified recovery
  transactions may change Hermes source.
- No automatic Gateway restart and no implicit system privilege escalation.

## 6. Acceptance Criteria

Automated acceptance covers configuration validation, profile isolation,
domain-separated auth/replay, policy hot reload, every runtime/direct-card path,
native-media call ownership, fenced table parsing, table compaction, serialized
budget handoff, stable per-chunk UUIDs, signed native ACK, delivery-ledger
restart recovery, integrity grace/timeout/recovery refusal, manager-selection
ownership, patch install/remove/restore, docs, and package metadata.

Release acceptance additionally requires:

1. full pytest and `git diff --check` on the feature branch and exact merge SHA;
2. public tagged install from outside the checkout with `site-packages`
   provenance;
3. real Feishu checks for card -> native -> card switching, a tool-bearing
   native answer, native commands/notices, `/hfc` card availability, six-table
   compaction, and one native size-budget handoff;
4. a local verified Hermes-upgrade integrity simulation that reaches
   `restart_required` without restarting Gateway;
5. Linux unit coverage for every service manager and an ordinary Docker Compose
   smoke;
6. public replies to Issues #157/#158/#159 and closure/supersession comments on
   PRs #156/#160 only after the replacement behavior is released.
