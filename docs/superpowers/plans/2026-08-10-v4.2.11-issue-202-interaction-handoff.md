# V4.2.11 Issue 202 Interaction Handoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release v4.2.11 so every successfully superseded streaming card becomes a green read-only `已转入交互卡片` snapshot while only the newest interaction card remains interactive.

**Architecture:** Keep the existing send-new-card promotion transaction in `server.py`. After the replacement send succeeds, cancel and await the predecessor animation, render a detached copy of the pre-request session, override only its completed handoff presentation, PATCH the old Feishu message best-effort, and then promote the replacement message id. No persistent session field, renderer mode, configuration option, or Hermes patch change is introduced.

**Tech Stack:** Python 3.9+, aiohttp, asyncio, Feishu Card JSON 2.0, pytest, pytest-asyncio, GitHub Actions.

## Global Constraints

- Preserve Issue #187 behavior: every `interaction.requested` still sends a fresh card at the bottom of the chat.
- A replacement send failure restores the canonical session and leaves the old card and animation authoritative and retryable.
- A predecessor PATCH failure is observable through existing update metrics and diagnostics but cannot fail an already delivered interaction.
- Cancel and await the predecessor animation before the final PATCH so no queued frame can overwrite the snapshot.
- The detached predecessor keeps visible answer, thinking, timeline, tools, attachments, routing identity, and prior completed interaction evidence; it clears transient runtime preview text and contains no new pending interaction or callback token.
- Callback authentication, chat/operator binding, interaction expiry, sequence idempotence, topic/reply routing, native gray-text suppression, `legacy/`, and the Hermes patch surface remain unchanged.
- Automated maintainer verification is the release gate; reporter confirmation is requested after release and is not a prerequisite for v4.2.11.
- Protect the main workspace untracked files `docs/code-review-v4.2.4-2026-08-01.md` and `docs/superpowers/plans/2026-08-01-v4.2.5-audit-fixes.md`.

- [ ] **Step 3: Implement the detached predecessor finalizer**

  Add a helper near the card animation helpers with this behavior:

  ```python
  async def _finalize_interaction_predecessor(
      app: web.Application,
      *,
      session_key: str,
      predecessor_message_id: str,
      bot_id: str | None,
      predecessor_snapshot: CardSession,
      animation_task: asyncio.Task[None] | None,
  ) -> bool:
      if animation_task is not None:
          animation_task.cancel()
          await asyncio.gather(animation_task, return_exceptions=True)

      predecessor_snapshot.active_interaction = copy.deepcopy(
          predecessor_snapshot.active_interaction
      )
      predecessor_snapshot.latest_tool_preview = ""
      predecessor_snapshot.runtime_phase_text = ""
      predecessor_snapshot.display_status = "completed"
      predecessor_snapshot.display_status_source = "explicit"
      card = _render_session_card_for_app(
          app,
          predecessor_snapshot,
          session_key=session_key,
      )
      card["header"] = {
          "template": "green",
          "title": card.get("header", {}).get(
              "title", {"tag": "plain_text", "content": app[CARD_TITLE_KEY]}
          ),
          "subtitle": {"tag": "plain_text", "content": "已转入交互卡片"},
      }
      card.setdefault("config", {}).setdefault("summary", {})["content"] = (
          "已转入交互卡片"
      )
      return await _update_card_for_app(
          app,
          predecessor_message_id,
          card,
          bot_id,
      )
  ```

  Keep this helper predecessor-only: it must not mutate `app[SESSIONS_KEY][session_key]`, `INTERACTION_RESULTS_KEY`, or `FEISHU_MESSAGE_IDS_KEY`.

  Extend the two private render wrappers with a keyword-only
  `session_key: str | None = None` argument. When supplied, use that key for
  `SESSION_CARD_CONFIGS_KEY` and interaction-mode lookup; all existing callers
  omit it and retain the current identity/fallback behavior. This is required
  for canonical `turn_id` and topic sessions whose key is not equal to the
  detached snapshot's `message_id`.
