# V4.2.10 Security And Interaction Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release v4.2.10 with authenticated non-loopback sidecar callbacks/reads, enforceable interaction expiry, stronger CI/security governance, and corrected release records.

**Architecture:** Add a domain-separated `hfc-sidecar-request-v1` HMAC proof that binds HTTP method, canonical path, and raw body, while preserving loopback process trust. Make interaction expiry a sidecar-owned absolute deadline; expired interactions transition to failed, update the existing card, reject late choices, and no longer block cleanup. Keep all changes inside HFC and do not expand the Hermes patch surface.

**Tech Stack:** Python 3.9+, aiohttp, HMAC-SHA256, pytest/pytest-asyncio, GitHub Actions, GitHub branch protection and security APIs.

## Global Constraints

- Do not read, rotate, dismiss, or otherwise mutate Secret Scanning alert #1.
- Default loopback deployments remain compatible and do not require transport proof.
- Non-loopback sensitive routes fail closed on missing, invalid, expired, cross-route, cross-method, or replayed proof.
- Callback token/chat checks remain defense in depth and are not treated as network authentication.
- `/events` remains single POST; a distinct timeout transition must not replay `interaction.requested`.
- Do not edit installed Hermes files directly; patcher behavior and `legacy/` remain unchanged.
- Tag only the exact green `main` merge SHA after full detached-worktree verification.
