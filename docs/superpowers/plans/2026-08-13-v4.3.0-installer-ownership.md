# V4.3.0 Installer Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the V4.3 installer bind one verified Hermes home, own opt-in plugin configuration reversibly, and preserve that ownership across install, repair, restore, uninstall, and maintenance update.

**Architecture:** This is Task 4 of the approved V4.3.0 plan. It consumes the reviewed Runtime Bridge production bootstrap and target-aware Hybrid Patcher interfaces and must not reimplement them. Add an installer-only `install/plugin.py` boundary for binding, isolated probe, config preimage and official plugin enable; use it from a manifest-v3 staged compensation transaction and phase-aware recovery.

**Tech Stack:** Python 3.9+, stdlib `dataclasses`/`hashlib`/`json`/`os`/`stat`/`subprocess`, PyYAML, pytest, Bash, PowerShell, Docker Compose.

## 2026-08-13 Fixed-tag correction gate

This gate corrects installer execution against Hermes `v2026.8.3` commit
`3c27eb6234bf91b8ceee9e9071591b31e9b148cb`; it does not change the approved
ownership or recovery product scope. **Tasks 1–8 are not executable until** the
Runtime plan has a signed production bootstrap plus real plugin-manager
subprocess proof and the Hybrid plan supplies fixed-tag-provenance,
target-aware aggregate patch APIs. Where this gate conflicts with a later code
sample, the sample is superseded.

1. **Runtime Python binding accepts a verified POSIX venv symlink.** The
   lexical path must be the selected checkout's venv launcher and must be
   inspected with `lstat`; on POSIX it may be a symlink. Resolve it without a
   loop, require the final target to be a regular executable, and bind identity
   to both lexical link metadata/target text and resolved target metadata.
   Execute the lexical launcher with `-I` and verify returned `sys.executable`,
   `sys.prefix`, `sys.base_prefix`, `sysconfig.get_paths()[purelib/platlib]`,
   distribution and import origin against the selected venv. A dangling,
   swapped, nonregular or wrong-prefix link refuses mutation. Continue to reject
   symlinked `HERMES_HOME`, config, private-state parents and ownership files.
2. **Preflight and post-enable verification are distinct.** The read-only
   preflight decision requires fixed-tag native callsite/kwargs/timing/
   entry-point probe facts and target-aware patch capabilities, but cannot
   require `plugin_enabled=true` before enable. Effective enable, exact entry
   point load and callback registration are post-enable/post-restart facts.
   The completed selector's `required_patch_groups` remains its flat logical
   set: fixed-tag Hybrid requires the exact four reviewed native capabilities
   and all 17 patch groups, including `subagent_parent_identity`. The descriptor
   registry must expand that set into a target→group
   mapping, and equality is checked per run/turn-context/turn-finalizer/
   approval/delegate/cron/Base target. Never compare
   `detect_patch_groups(run.py)` to the global logical set.
3. **Install is one staged compensation transaction.** Finish all read-only
   target/original rendering and preflight first. Starting with the first
   preimage/journal write, one outer `try` owns: `prepared` evidence → official
   enable and semantic verification → `plugin_enabled` evidence → aggregate
   source commit → installed verification → `installed` evidence. Every fault
   point (each phase write, enable timeout/nonzero/semantic drift, each target
   write, manifest write and final probe) has a test. Compensation restores
   every newly written source target, restores config only when its current hash
   equals the recorded HFC postimage, restores the exact previous manifest, and
   validates convergence before deleting new evidence. If compensation is
   unsafe or incomplete, retain journal/backups with a truthful recoverable
   phase and return nonzero; never report install success.
4. **Legacy dispatch precedes v3 binding requirements.** V1, V2 and supported
   manifestless Legacy source-only restore/uninstall keep their existing
   verified backup/hash/marker route and do not require `--hermes-home`, an
   entry point, or a config preimage that did not exist. They never modify
   plugin config. A V2→V3 *install/migration* does require the new exact binding
   and all aggregate verified originals. V3 restore/uninstall/repair uses the
   binding and config ownership rules. Unprovable manifestless state goes to
   manual review without mutation. Tests must cover V1, V2 and manifestless
   source-only restore and uninstall separately from V2→V3 migration.
5. **Cross-mode source is installer-verified and aggregate.** The installer,
   not `patcher.remove_*`, establishes each original from manifest target
   identity, current patched hash, backup hash and strict current marker body.
   It supplies all target originals to one aggregate renderer and commits or
   compensates the set together. Missing one required target/original,
   mixed-mode markers, target drift or a partial backup refuses before write.
6. **Maintenance binding is recoverable without guessing.** Persist a random
   opaque `binding_ref` in the redacted job and keep its absolute target mapping
   only in a separate private `0700/0600`, no-follow binding registry. Resolve
   the reference, revalidate lexical/resolved Python, checkout/home/config
   identities and ownership hashes before restore and again after the official
   updater. A hash-only job with no protected path binding is not executable;
   do not scan homes or choose the only/recent candidate. Keep the registry,
   journal and backups on recoverable failure, and delete the binding record
   only after verified reinstall or verified cancellation cleanup.
7. **Corrected dependency order:** Runtime corrected Task 6/bootstrap/Task 7 →
   Hybrid fixed-tag capability and aggregate APIs → Installer Task 1 POSIX
   binding/probe → Task 2 preimage/enable → Task 3 aggregate manifest schema →
   corrected Task 4 transaction → Task 5 legacy split/migration → Task 6
   recovery → corrected Task 7 maintenance binding → Task 8 script forwarding.

```python
# hermes_feishu_card/install/plugin.py
@dataclass(frozen=True)
class HermesRuntimeBinding:
    checkout_root: Path
    runtime_python: Path
    python_identity: str
    hermes_home: Path
    config_path: Path


def resolve_runtime_binding(*, checkout_root: Path, hermes_home: str | Path | None, profile_id: str | None) -> HermesRuntimeBinding:
    if hermes_home is None and profile_id:
        raise RuntimeBindingRefused("Hermes home is required; --profile-id is not a Hermes home selector")
    candidates = _binding_candidates(checkout_root, hermes_home)
    if not candidates:
        raise RuntimeBindingRefused("Hermes home is required; pass --hermes-home")
    if len(candidates) != 1:
        raise RuntimeBindingRefused("Hermes home is ambiguous; pass --hermes-home")
    return _verify_binding(candidates[0], checkout_root)


def probe_plugin_entrypoint(binding: HermesRuntimeBinding) -> PluginEntrypointProbe:
    completed = subprocess.run(
        [str(binding.runtime_python), "-I", "-c", _ENTRYPOINT_PROBE_CODE],
        check=False, capture_output=True, text=True, timeout=30, cwd=str(binding.checkout_root),
    )
    return _parse_entrypoint_probe(completed, binding)
```

`_binding_candidates` accepts, in this order, an explicit `--hermes-home`, then current-process `HERMES_HOME` only if checkout/runtime/config identities match, then exactly one supported parent-home layout. `_verify_binding` rejects symlinked home/config and missing regular config. For the runtime Python it follows the correction gate: a POSIX venv launcher symlink is valid only after lexical-link, resolved-target, executable, prefix and site-packages identity checks; “nonregular lexical path” alone is not a rejection. `_ENTRYPOINT_PROBE_CODE` emits one JSON object containing `candidates`, `package_location`, `executable`, `prefix`, `base_prefix`, `purelib`, and `platlib`; it must query `importlib.metadata.entry_points(group="hermes_agent.plugins")` and distribution metadata without importing checkout code.

Add `--hermes-home` to the parser for `setup`, `install`, `repair`, `restore`, `uninstall`, `doctor`, `status`, and maintenance commands that reconnect to an installed target. Pass `args.hermes_home` to `resolve_runtime_binding`; do not change any final human-readable doctor/status formatting in this task.

```python
# hermes_feishu_card/install/plugin.py
def prepare_plugin_config(binding: HermesRuntimeBinding, previous_manifest: Mapping[str, object] | None) -> PluginConfigPreimage:
    state_dir = _private_state_dir(binding.hermes_home)
    _create_private_directory(state_dir, mode=0o700)
    config_bytes = _read_regular_file(binding.config_path)
    backup_id = f"hfc-config-preimage-{uuid4().hex}"
    backup_path = state_dir / backup_id
    journal_path = state_dir / f"{backup_id}.journal.json"
    _write_private_file(backup_path, config_bytes, mode=0o600)
    _write_private_file(journal_path, _prepared_journal(binding, backup_id, config_bytes, previous_manifest), mode=0o600)
    return PluginConfigPreimage(state_dir, backup_id, backup_path, journal_path, sha256_bytes(config_bytes), normalize_yaml(config_bytes))


def enable_plugin(binding: HermesRuntimeBinding, preimage: PluginConfigPreimage) -> PluginOwnership:
    before_enabled = _plugin_effectively_enabled(preimage.normalized_tree, "hermes-feishu-card")
    if not before_enabled:
        _run_official_plugin_enable(binding, "hermes-feishu-card")
    after_bytes = _read_regular_file(binding.config_path)
    after_tree = normalize_yaml(after_bytes)
    _assert_only_owned_plugin_diff(preimage.normalized_tree, after_tree)
    _assert_plugin_effectively_enabled(after_tree, "hermes-feishu-card")
    _assert_tool_override_false(after_tree, "hermes-feishu-card")
    return PluginOwnership(before_enabled, not before_enabled, preimage.pre_sha256, sha256_bytes(after_bytes), preimage.config_backup_id, sha256_file(preimage.config_backup_path))
```

`_run_official_plugin_enable` invokes the bound runtime Python with the official Hermes noninteractive plugin-enable command and exactly the bound `HERMES_HOME`; it returns nonzero/timeout as `PluginConfigRefused`. `_assert_only_owned_plugin_diff` compares normalized YAML trees in memory, accepts only the three global-constraint fields, and rejects all other semantic edits. If pre-existing enable is effective and nonconflicting, it makes no config write and returns `added_by_hfc=False`. Journal JSON records fixed-format backup ID, pre/post hashes, binding identity hashes, previous manifest bytes/hash, and phase; it must never include the raw config bytes.

```python
# hermes_feishu_card/install/manifest.py
CURRENT_INSTALL_MANIFEST_VERSION = 3
INSTALL_PHASES = frozenset({"prepared", "plugin_enabled", "installed"})
PLUGIN_FIELDS = frozenset({"key", "entry_point", "distribution", "version", "python_identity"})
PLUGIN_CONFIG_FIELDS = frozenset({"enabled_before", "added_by_hfc", "pre_sha256", "post_sha256", "config_backup_id", "backup_sha256"})


def _validate_v3_integration(manifest: Mapping[str, object]) -> None:
    if manifest.get("phase") not in INSTALL_PHASES:
        raise ManifestVersionError(UNSUPPORTED_INSTALL_MANIFEST_VERSION_MESSAGE)
    integration = _mapping(manifest.get("integration"), "integration")
    _validate_exact_group(integration, {"mode", "capability_fingerprint", "patch_groups", "patch_targets", "plugin", "plugin_config"}, "integration")
    _validate_exact_group(_mapping(integration["plugin"], "plugin"), PLUGIN_FIELDS, "plugin ownership")
    config = _mapping(integration["plugin_config"], "plugin_config")
    _validate_exact_group(config, PLUGIN_CONFIG_FIELDS, "plugin config ownership")
    _validate_backup_id(config["config_backup_id"])
    _validate_portable_relative_paths(manifest)
```

It records only binding identity digest in `plugin.python_identity`; it does not record `hermes_home`, `config_path`, backup filesystem path, raw YAML, secret-derived strings, chat IDs, or session IDs. `phase="prepared"` has a complete preimage record with `post_sha256` set to the pre-image hash; `plugin_enabled` and `installed` replace it with the verified post-image hash.
